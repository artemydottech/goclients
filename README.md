# goclients

Проект для обучения. Готовая инфраструктура для **selfhosted** разворачивания аналога сервиса [`yclients`](https://www.yclients.com/) с использованием **Go, SQLite**.

## Быстрый старт

Для компиляции `go-sqlite3` требуется установка `GCC` сервиса.

```bash
git clone https://github.com/artemydottech/goclients.git
cd goclients
cp .env.example .env
go mod tidy
go run .
```

Схема создаётся и обновляется на старте: пронумерованные миграции из
`internal/repository/migrations.go` применяются по порядку, применённые версии
хранятся в таблице `schema_migrations`. Новая миграция — новая запись в списке
`migrations` с номером на единицу больше последнего.

```bash
make check      # gofmt, vet, test -race и build, как в CI
```

## Переменные окружения

| Переменная       | По умолчанию | Назначение                                       |
| ---------------- | ------------ | ------------------------------------------------ |
| `DB_PATH`        | `./data.db`  | файл базы SQLite                                 |
| `PORT`           | `8080`       | порт HTTP-сервера, число от 1 до 65535           |
| `LOG_LEVEL`      | `info`       | `debug`, `info`, `warn` или `error`              |
| `MAX_BODY_BYTES` | `1048576`    | максимальный размер тела запроса в байтах        |
| `REMINDER_INTERVAL` | `1m`      | как часто искать записи для напоминания, `0` выключает |
| `REMINDER_LEAD`  | `24h`        | за сколько до начала записи напоминать           |
| `DEBUG_ENDPOINTS` | `false`     | включает `/debug/vars` и `/debug/pprof/`         |

Неверное значение останавливает сервер на старте с понятной ошибкой.

## Модель данных

```
компания ──┬── сотрудники ──┬── услуги, которые он оказывает
           │                ├── недельный график работы с перерывом
           │                └── отпуска и больничные
           ├── услуги (название, длительность, цена)
           ├── клиенты (уникальны по телефону внутри компании)
           └── записи (клиент + сотрудник + услуга + время)
```

Всё, что принадлежит компании, удаляется вместе с ней.

### Часовой пояс

У компании есть поле `timezone` — имя пояса IANA, по умолчанию `UTC`:

```json
{ "name": "Ромашка", "timezone": "Asia/Yekaterinburg" }
```

График («10:00») читается в этом поясе, слоты возвращаются в местном времени
со смещением (`2026-10-01T10:00:00+05:00`). Неизвестный пояс — `400`.

| Метод    | Путь               | Ответ                        |

| `DELETE` | `/users/{id}`      | `204`                        |
| `POST`   | `/companies`       | `201` + `{"id": <int64>}`    |
| `GET`    | `/companies`       | `200` + массив компаний      |
| `GET`    | `/companies/{id}`  | `200` + компания             |
| `PUT`    | `/companies/{id}`  | `204`, тело как при создании |
| `DELETE` | `/companies/{id}`  | `204`                        |
| `POST`   | `/employees`       | `201` + `{"id": <int64>}`    |
| `GET`    | `/employees`       | `200` + массив сотрудников   |
| `GET`    | `/employees/{id}`  | `200` + сотрудник            |
| `PUT`    | `/employees/{id}`  | `204`, `company_id` не меняется |
| `DELETE` | `/employees/{id}`  | `204`                        |

## Услуги

| Метод    | Путь                      | Ответ                     |
| -------- | ------------------------- | ------------------------- |
| `POST`   | `/services`               | `201` + `{"id": <int64>}` |
| `GET`    | `/services`               | `200` + массив услуг      |
| `GET`    | `/services?company_id=1`  | `200` + услуги компании   |
| `GET`    | `/services/{id}`          | `200` + услуга            |
| `PUT`    | `/services/{id}`          | `204`, `company_id` не меняется |
| `DELETE` | `/services/{id}`          | `204`                     |
| `GET`    | `/services/{id}/employees`| `200` + мастера услуги    |

```json
{
  "company_id": 1,
  "name": "Стрижка",
  "description": "Мужская",
  "duration": 45,
  "price": 1500
}
```

`duration` — минуты, от 1 до 1440: из неё считается конец записи.

## Кто какие услуги оказывает

| Метод | Путь                       | Ответ                    |
| ----- | -------------------------- | ------------------------ |
| `PUT` | `/employees/{id}/services` | `204`                    |
| `GET` | `/employees/{id}/services` | `200` + услуги сотрудника|

```json
{ "service_ids": [1, 2, 5] }
```

`PUT` заменяет набор целиком. Услуга чужой компании в списке — `400`.

## График работы

| Метод | Путь                       | Ответ                  |
| ----- | -------------------------- | ---------------------- |
| `PUT` | `/employees/{id}/schedule` | `204`                  |
| `GET` | `/employees/{id}/schedule` | `200` + рабочие дни    |

```json
{
  "days": [
    { "weekday": 1, "starts_at": "10:00", "ends_at": "20:00" },
    {
      "weekday": 2, "starts_at": "10:00", "ends_at": "20:00",
      "break_starts_at": "13:00", "break_ends_at": "14:00"
    }
  ]
}
```

`weekday` — от `0` (воскресенье) до `6`. День, которого нет в списке, считается
выходным. Перерыв необязателен, но если указан — целиком и внутри рабочего дня.

## Отпуска и больничные

| Метод    | Путь                       | Ответ                     |
| -------- | -------------------------- | ------------------------- |
| `POST`   | `/employees/{id}/time-off` | `201` + `{"id": <int64>}` |
| `GET`    | `/employees/{id}/time-off` | `200` + периоды           |
| `DELETE` | `/time-off/{id}`           | `204`                     |

```json
{
  "starts_at": "2026-10-10T00:00:00+05:00",
  "ends_at": "2026-10-20T00:00:00+05:00",
  "reason": "отпуск"
}
```

Период вычитается из слотов и блокирует запись. Поставить его поверх
активных записей нельзя — сначала их нужно перенести или отменить.

## Клиенты

| Метод    | Путь                     | Ответ                     |
| -------- | ------------------------ | ------------------------- |
| `POST`   | `/clients`               | `201` + `{"id": <int64>}` |
| `GET`    | `/clients`               | `200` + массив клиентов   |
| `GET`    | `/clients?company_id=1`  | `200` + клиенты компании  |
| `GET`    | `/clients/{id}`          | `200` + клиент            |
| `PUT`    | `/clients/{id}`          | `204`, `company_id` не меняется, телефон уникален в компании |
| `DELETE` | `/clients/{id}`          | `204`                     |
| `GET`    | `/clients/{id}/stats`    | `200` + статистика визитов |

Телефон нормализуется до цифр `0-9`, поэтому `+7 (999) 123-45-67` и `79991234567` —
один и тот же клиент. Повторный номер в той же компании — `400`.

```json
{
  "client_id": 1,
  "appointments": 7,
  "completed_visits": 2,
  "no_shows": 1,
  "cancelled": 2,
  "upcoming": 2,
  "total_spent": 3500,
  "last_visit_at": "2026-10-05T12:00:00Z",
  "next_visit_at": "2026-10-17T12:00:00Z"
}
```

`total_spent` считается только по завершённым визитам и по цене на момент
записи.

## Записи

| Метод    | Путь                            | Ответ                     |
| -------- | ------------------------------- | ------------------------- |
| `POST`   | `/appointments`                 | `201` + `{"id": <int64>}` |
| `GET`    | `/appointments`                 | `200` + все записи        |
| `GET`    | `/appointments?client_id=1`     | `200` + записи клиента    |
| `GET`    | `/appointments?employee_id=1`   | `200` + календарь мастера |
| `GET`    | `/appointments/{id}`            | `200` + запись            |
| `PUT`    | `/appointments/{id}/status`     | `204`                     |
| `PUT`    | `/appointments/{id}/time`       | `200` + перенесённая запись |
| `DELETE` | `/appointments/{id}`            | `204`                     |

```json
{
  "client_id": 1,
  "employee_id": 2,
  "service_id": 3,
  "starts_at": "2026-10-01T10:00:00Z",
  "comment": "первый визит"
}
```

`ends_at` и `price` не принимаются: конец считается из длительности услуги,
цена фиксируется из прайса в момент записи и дальше не меняется — ни при
переносе, ни при смене прайса.
Выборка по мастеру берёт ближайшую неделю; окно задаётся `from` и `to` в RFC3339.

Статусы: `pending` (по умолчанию), `confirmed`, `cancelled`, `completed`,
`no_show` (клиент не пришёл). Новая запись создаётся только как `pending` или
`confirmed`. Отменённая запись освобождает слот, остальные — занимают.

| Из          | Можно перевести в                            |
| ----------- | -------------------------------------------- |
| `pending`   | `confirmed`, `cancelled`, `completed`, `no_show` |
| `confirmed` | `cancelled`, `completed`, `no_show`          |
| `cancelled`, `completed`, `no_show` | никуда — это конечные статусы |

`completed` и `no_show` ставятся только после начала записи. Отменённую запись
вернуть нельзя: её слот мог уже занять другой клиент, поэтому нужна новая
запись.

Запись отклоняется с `400`, если:

- время в прошлом;
- у мастера выходной, отпуск или перерыв, либо запись выходит за рабочий день;
- сотрудник не оказывает эту услугу;
- клиент, сотрудник и услуга из разных компаний;
- интервал пересекается с другой записью этого мастера.

Проверка пересечения и вставка идут одной транзакцией: два одновременных
запроса на один слот не создадут две записи.

### Перенос

```json
{ "starts_at": "2026-10-01T15:00:00+05:00", "employee_id": 4 }
```

`employee_id` необязателен — без него запись остаётся у того же мастера.
Перенос проходит все проверки новой записи; переносить можно только
`pending` и `confirmed`.

## Свободные слоты

```
GET /slots?employee_id=2&service_id=3&date=2026-10-01&step=15
```

Отдаёт массив моментов в RFC3339, на которые можно записаться: рабочий день
мастера за вычетом записей, перерыва, отпусков и уже прошедших часов. Дата
понимается в поясе компании. `step` — шаг сетки
в минутах, по умолчанию `15`. В выходной возвращается пустой массив.

Параметр `company_id` в списках услуг и клиентов должен быть положительным целым числом.

## Постраничная выдача

Списки `/companies`, `/employees`, `/services` и `/clients` принимают `limit` и
`offset`:

```
GET /services?company_id=1&limit=20&offset=40
```

Без параметров возвращаются все записи, как раньше. `limit` не больше `200`,
`offset` не меньше `0`, иначе `400`. Порядок стабильный: по возрастанию `id`.

## Напоминания

Фоновый воркер раз в `REMINDER_INTERVAL` ищет записи в статусе `pending` и
`confirmed`, которые начнутся в ближайшие `REMINDER_LEAD`, и отправляет по ним
уведомление. Сейчас уведомление пишется в лог (`appointment reminder`, с именем
и телефоном клиента). Отправленные записи помечаются в `appointments.reminded_at`,
поэтому повторно напоминание не уходит. Если отправка не удалась, запись не
помечается и воркер повторит попытку на следующем проходе. `REMINDER_INTERVAL=0`
выключает воркер. При остановке сервера воркер дожидается завершения.

## Служебные эндпоинты

| Метод | Путь       | Ответ                                                      |
| ----- | ---------- | ---------------------------------------------------------- |
| `GET` | `/healthz` | `200` пока процесс жив                                     |
| `GET` | `/readyz`  | `200`, если база отвечает на ping, иначе `503`             |

Каждый ответ содержит заголовок `X-Request-ID`. Если клиент прислал свой, он
сохраняется, иначе генерируется новый. Тот же id попадает в лог запроса.

### Отладка

С `DEBUG_ENDPOINTS=true` появляются `GET /debug/vars` (счётчики запросов
`http_requests_total`, `http_requests_by_status_class`, `http_response_bytes_total`
и стандартные метрики Go через `expvar`) и `GET /debug/pprof/`. По умолчанию они
выключены: не открывайте их наружу без закрытого периметра.

## Коды ошибок

Идентификаторы `{id}` должны быть положительными целыми числами, иначе `400`.
Обязательные названия и имена, состоящие только из пробелов, отклоняются с `400`
при создании и обновлении компаний, сотрудников, услуг и клиентов.
Тело запроса должно содержать ровно одно JSON-значение, отличное от `null`.
Лишние значения и текст после JSON отклоняются с `400`.
Лимит `MAX_BODY_BYTES` действует на всё тело, включая пробелы после JSON.

| Код   | Когда                                                          |
| ----- | -------------------------------------------------------------- |
| `400` | тело не разбирается или не прошло валидацию                      |
| `404` | записи с таким `id` нет                                          |
| `405` | метод не совпал с маршрутом                                      |
| `413` | тело запроса больше `MAX_BODY_BYTES`                             |
| `500` | сбой хранилища                                                   |

Тело любой ошибки одинаковое:

```json
{ "error": "user not found" }
```

### Соц. сети компании

Поле `socials` — объект, где ключом может быть только `vk`, `telegram`,
`whatsapp` или `viber`. Любой другой ключ отклоняется с `400`.

```json
{
  "name": "Ромашка",
  "socials": { "vk": "vk.com/romashka", "telegram": "@romashka" }
}
```
